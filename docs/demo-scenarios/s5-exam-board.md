# S5 — Exam Board and Ratification

**Slug:** `exam-board` · **Reference date:** 2026-07-31 · **Students:** 1,000

```bash
pnpm demo:reset exam-board
```

---

## What this scenario contains

This is the post-ratification snapshot. Exam boards have met and their decisions have been locked. Progression and award decisions are recorded. Module results are confirmed. Students can view their final marks. This scenario is used to demonstrate the exam board governance journey and the corrections workflow.

---

## Stories

### P-09 — View marks and results

**Persona:** `alice.demo` · **Role:** Enrolled student · **App:** Student portal · **URL:** http://localhost:5174/results

> Alice's exam board has met and ratified its decisions. She wants to check her final module results.

**Steps:**

1. Log in to the student portal as `alice.demo`.
2. Navigate to **Results** in the top navigation bar, or go to `/results`.
3. You should see Alice's module results for the current academic year. Each row shows the module, credit value, raw mark, grade, and outcome (pass/fail/referral).
4. Confirm the results page shows a summary at the top: total credits passed, overall classification band, or progression outcome.
5. Note that results are grouped by enrolment period — if Alice has multiple years of study, previous years appear below.

### EB-01 — Browse the exam boards list

**Persona:** `chair` · **Role:** Exam Board Chair · **App:** Admin console · **URL:** http://localhost:5173/exam-boards

> The exam board chair needs to find the undergraduate honours board for the current year to begin the ratification review.

**Steps:**

1. Log in to the admin console at http://localhost:5173 as `chair`.
2. Navigate to **Exam Boards** (`/exam-boards`) from the left sidebar.
3. You should see a list of exam boards. Each row shows the board type, academic year, meeting date, and ratification status.
4. In S5, boards should be visible and some should be ratified (green **ratified** badge). Others may still show **pending**.
5. Use the **Academic year** filter to narrow the list to `2025/26`.
6. Locate an undergraduate honours board and note its meeting date.

---

### EB-02 — Review an exam board — agenda and data pack

**Persona:** `chair` · **Role:** Exam Board Chair · **App:** Admin console · **URL:** http://localhost:5173/exam-boards

> Before the ratification meeting, the chair needs to review the board's agenda, candidate list, and data pack.

**Steps:**

1. From the exam boards list, select **Open →** on an undergraduate honours board.
2. You are taken to the **Exam Board Detail** page. You start on the **Overview** tab.
3. Review the Overview tab: board type, academic year, academic period, and meeting date.
4. Note the **Generate exam entries** section — this creates timetable entries for all candidates. In S5, entries are already generated.
5. Note the **VLE connector** panel showing the VLE integration status for this board.
6. Select the **Entries** tab to see all exam entries associated with this board, filtered by module and candidate.
7. Review a few entries: candidate number, module, paper, sitting date, and special arrangements.

---

### EB-03 — Review candidate profiles and progression decisions

**Persona:** `chair` · **Role:** Exam Board Chair · **App:** Admin console · **URL:** http://localhost:5173/exam-boards

> The chair needs to review individual candidate profiles — marks, EC claims, and adjustments — before the board makes its progression decisions.

**Steps:**

1. From the exam board detail page, select the **Candidates** tab.
2. You should see a list of candidates (students registered for modules covered by this board). Each row shows the student name, student number, and current overall position.
3. Select a candidate to open their profile within the board context.
4. Review the candidate's marks by module, any approved EC claims, and any active learning adjustments.
5. Note the progression recommendation shown — this may be automatically generated by the academic rules engine based on the marks and credits passed.
6. Review several candidates to get a sense of the spread of outcomes.

### EB-04 — Review ratified award decisions

**Persona:** `chair` · **Role:** Exam Board Chair · **App:** Admin console · **URL:** http://localhost:5173/exam-boards

> The board has met and the chair needs to confirm the ratification and sign off the decisions.

**Steps:**

1. From the exam board detail page, select the **Sign-off** tab.
2. The sign-off tab shows the ratification status and any outstanding actions.
3. In S5, boards are already ratified. Review the ratification record: who ratified, when, and any attached notes.
4. Confirm the ratification timestamp is present and the board status shows **ratified**.
5. Navigate back to the exam boards list (`/exam-boards`) and confirm the board now shows a **ratified** badge in the list.

### CO-01 — Raise a correction case against a board decision

**Persona:** `registry` · **Role:** Registry Administrator · **App:** Admin console · **URL:** http://localhost:5173/students

> A student has contacted the registry to dispute a module mark. The registry administrator needs to raise a formal correction case.

**Steps:**

1. Log in as `registry` and navigate to **Students** (`/students`).
2. Search for a student and open their record.
3. Select the **Corrections** tab on the student detail page.
4. Review any existing correction cases. In S5, there may be pre-seeded cases.
5. Select **Raise correction** (or the equivalent action). A form appears.
6. Select the affected module from the dropdown. Enter the nature of the correction and the grounds for challenge.
7. Submit the correction case. Confirm it appears in the Corrections tab with a status of **open**.

---

### CO-02 — Progress and resolve a correction case

**Persona:** `registry` · **Role:** Registry Administrator · **App:** Admin console · **URL:** http://localhost:5173/students

> The registry administrator needs to progress an open correction case through its workflow steps and record the outcome.

**Steps:**

1. Log in as `registry` and navigate to the student record where you raised the correction case in story CO-01.
2. Select the **Corrections** tab. Locate the open correction case.
3. Review the case timeline — the workflow steps should be visible.
4. Check the **Tasks** inbox (`/tasks`) for any pending task associated with this correction. If a task exists, complete it as described in story TI-01.
5. Return to the Corrections tab. If the workflow has advanced, the case status should have moved to the next stage.
6. To resolve the case, select the resolution action and choose an outcome: **upheld**, **partially upheld**, or **dismissed**. Record the outcome rationale.
7. Submit the resolution. The case status should update to **resolved**.
