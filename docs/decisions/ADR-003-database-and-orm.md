# ADR-003: Database and ORM

**Status**: Accepted
**Date**: 2026-06-04

## Context

The persistence layer must be a relational database (principle §8) with PostgreSQL as the stated preference. An ORM or query builder must be selected that supports TypeScript type safety, controlled schema migrations, and the bitemporal data patterns required by principle §3. Row-level security policies (principle §6) are enforced at the database layer.

## Decision

**PostgreSQL 16** as the relational database engine.
**Drizzle ORM** as the TypeScript database access layer and migration toolchain.

## Rationale

**PostgreSQL 16**
- Strongest open source relational database; free (PostgreSQL Licence).
- Native support for the data types used in the SRS domain: `uuid`, `timestamptz`, `jsonb`, `enum`, `range` types.
- Row-level security policies enforced natively at the database layer.
- Excellent support for bitemporal patterns via `tstzrange` range types and exclusion constraints.
- Mature extension ecosystem (`pgcrypto`, `pg_trgm` for full-text search).
- Widely understood and operated by HE institution DBAs.

**Drizzle ORM**
- SQL-transparent: generated queries are predictable and inspectable; no hidden query patterns.
- Full TypeScript inference from schema definition through to query results — no manual type casting.
- `drizzle-kit` provides version-controlled, deterministic schema migrations with a diff-based approach.
- Lightweight: no code generation step, no separate client binary; the schema is the type source.
- Supports raw SQL escape hatches for complex bitemporal queries without fighting the ORM.
- Free and open source (Apache 2.0 licence).

## Alternatives Considered

| ORM | Reason rejected |
|---|---|
| Prisma | Generates a separate type-safe client; migration workflow less transparent; heavier; schema DSL separate from TypeScript |
| TypeORM | Weaker type inference; active record pattern conflicts with domain model approach; migration tooling less reliable |
| Knex | Query builder only; no schema inference or migration diff tooling |
| Sequelize | JavaScript-first; TypeScript support bolted on; less type-safe |

## Consequences

- Database schema is defined in TypeScript using Drizzle schema files; migrations are generated by `drizzle-kit generate` and applied by `drizzle-kit migrate`.
- Bitemporal columns (`valid_from`, `valid_to`, `recorded_at`, `recorded_until`) are defined as reusable Drizzle column helpers and applied consistently across all temporal tables.
- Row-level security policies are defined in migration files alongside the schema; application code sets the tenant context via a session variable before executing queries.
- Raw SQL is acceptable for complex analytical or bitemporal queries where Drizzle's query builder would obscure intent.
