# Current Capability Matrix

> Status: Authoritative working baseline
> Evidence date: 2026-11-18
> Application maturity: Alpha — analysis and implementation convergence

[Product documentation](README.md) · [Business process inventory](../business-processes/process-inventory.md) · [Target data-model delta](../architecture/business-process-data-model-delta.md) · [Per-process coverage](../business-processes/traceability-matrix.md#implementation-coverage)

This matrix rates capabilities. How far each of the 49 academic-journey processes can be carried out in the app is rated, with evidence, in the per-process coverage table (checked 2026-11-18: 43 on screen, 6 on screen with a simulated link). Journey capabilities are rated against the Phase 5 D-46 test, and each names its principal-path tests, which `check:capability-baseline` verifies.

The work behind each material limitation is a row in the [backlog](backlog.md), whose Source ref is the capability ID; add a row there when a limitation is added here.

## Status definitions

| Status | Required meaning |
|---|---|
| **Implemented baseline** | Relevant physical schema and application service/API exist, with a usable UI or integration surface where appropriate and automated evidence for the principal path |
| **Partial** | Useful implementation exists, but the reviewed process boundary, authority, data lifecycle, integration or verification is incomplete |
| **Approved target** | Architecture and requirements are approved for delivery but the application is not complete |
| **Proposed target** | Research/design exists but still requires SME or architecture approval |
| **Not assessed** | Evidence has not yet been reconciled |

“Implemented baseline” does not mean production-ready for every institution or process variant.
